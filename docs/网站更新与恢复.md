## 以后如何使用

修改静态文件后，可双击项目根目录Site-Release.cmd。它检查并生成材料，成功后打开本地结果；不会替本人上传或失效。检查失败时保留提示，不生成可用发布目录。

默认读取.local/site-releases/published-reference.json作为已确认发布的比较基准（只有发布核对后才记录它）。没有该记录时生成全量本地参考快照，不把未发布草稿自动当已发布基准。也可由助手指定已有参考版本生成增量包。

输出含：

| 文件/目录 | 用途 |
| --- | --- |
| upload/ | 仅本次新增/变化文件，按桶根相对路径组织 |
| update.zip | 同一批变更文件的压缩副本 |
| snapshot.zip | 全部静态源文件及内置哈希清单，用于恢复副本 |
| manifest.json | 文件哈希、变更、未自动执行的删除项、检查结果、Git参考版本 |
| invalidation-paths.json | 本次建议失效路径；JS/CSS末尾*覆盖查询串版本 |

Git参考版本会标明存在本地未提交修改；此时包内哈希才精确描述当前静态源码，不把归档称为已提交/推送。恢复只允许项目.local/site-releases下的新目录，拒绝覆盖dist和已有文件，也不执行自动云端删除。

恢复由助手用`site_release.py restore 快照ZIP 新副本目录`完成并核对，文档用于保存工作，不要求本人独立照长手册回退。后续需要恢复时先定位对应包和受影响文件，再给本人当前环节的实际上传步骤。
